# 共存模組效能比較設計

目的：降低 Cookie Payback Planner 統計更新造成的主執行緒尖峰，優先維持推薦品質。

## 實驗方案

| 方案 | 實作範圍 | 正確性界線 |
|---|---|---|
| baseline | 目前來源版本的原始等待估算與既有搜尋設定 | 作為同版參考；實際設定隨報告保存 |
| indexed | 單次同步更新內建立暫時增益結構索引 | 每次查詢仍讀時間、倍率變更與即時收益 |
| compiled | 以同一索引預編譯等待時間分段 | 與原公式比較，保留乘法順序；不取代遊戲收益引擎 |
| search | 使用既有 A* 取代目前搜尋設定 | 視為獨立策略候選，排序與首選不同不得直接宣稱等價 |

不預編譯整個 Game.CalculateGains：共存模組可注入效果，遊戲也會讀取時間與迷你遊戲狀態。保留原引擎作為收益真值。

## 量測與資料保護

- Windows 使用原生工具；以執行檔實際路徑、主程序、CDP 目標共同確認實例。
- 相同執行檔共用啟動鎖；已有程序而連線失敗時拒絕重開，關閉僅限身分吻合的 owned 程序。
- 先保存正式遊戲，再正常關閉。獨立複製遊戲、存檔、模組與使用者資料；只在副本停用 Steam native bridge。
- 每組從驗證過的相同存檔快照開始，暖機 15 秒、採樣 60 秒、重複 3 次，以固定種子打亂四方案順序。
- 保存 CPU 原始採樣、各更新階段耗時、畫格間隔、長任務、模組版本／順序／腳本雜湊及實際設定。
- 頁面必須可見且更新與畫格樣本數皆非零；背景、空樣本或截斷資料明確標為無效。

## 品質與採用條件

在同一同步遊戲狀態及固定查詢時間下，比較所有項目的收益分數、等待時間、購買數量、策略排序、實際商店排序與自動購買首選。數值容差為相對誤差 1e-10；例外後須還原查詢時間與沙盒。

相同存檔位元組不保證相同執行期狀態：離線收益、隨機事件及其他模組計時仍可能不同。跨試驗嚴格比較狀態、設定、模組及腳本指紋；不同時只列觀測結果，不能自動選定因果勝者。最終採用須同時有品質與效能證據，不以平均 CPU 或單次最快值判斷。

## 驗證

來源檢查：TypeScript、oxlint、Vitest 與 esbuild。
工具檢查：Node 內建測試涵蓋互斥、程序 ownership、清理、隔離存檔、變體還原、分位數、有效性及錯誤處理。
實際驗證：先以短測確認模組載入與品質，再進行完整實驗，最後恢復正式遊戲。

## 嚴格產量投影支援契約

`productionProjectionEnabled` 自2053.73起預設開啟；`experimentalBatch`近似仍預設關閉。投影先驗證來源與資料，以相同數值快照建立基底，每一步只疊加該建築數量，依賴模型重算受影響倍率；不直接修改遊戲的amount／bought。每項成功試算仍執行一次原生CalculateGains，保留基底刷新。

目前接管條件：遊戲2.053、已知收益／價格函式來源、原生建築順序、空效果hooks或已知空CCSE relay、有效有限數值、購買1／10／100。包含Cursor／Grandma及有限正數timed buff，等待與銀行計算沿用原生路徑；未知版本／函式／hook、Cursed finger、ages／Century egg走原沙盒。普通非special tier只在整批購買完成後疊加擁有狀態；cookie／prestige／自訂價格等不支援。Pantheon必須在正常載入時取得可信launch→init→helper來源綁定，既有或未知helper不追認。

資料guard拒絕已涵蓋讀寫路徑上的getter、setter、繼承資料及未知callback；函式來源與閉包來源分別驗證。這不能證明任意Proxy或第三方副作用等價。已部署版有同輸入品質、原生輸出、自然負載與獨立審查證據，仍只覆蓋明確支援邊界與測試模組組合，不代表全面相容；詳見結果報告的2053.73驗收。

接管前另以零變更分支計算基底，要求 cookiesPsRaw 與 unbuffedCps 逐值等於遊戲目前數值；不一致以 base-production 回退。這能攔截已反映於基底的模型差異或未刷新狀態，但不能證明購買後的依賴與副作用等價。採精確比較，浮點運算次序差異亦可能降低接管率；須以實際接管數確認效能收益。

## 未來遊戲版本相容性：使用者最新約束

產品以遊戲原生試算作為收益真值，保留原生完整回退；不改寫原生CalculateGains／Has。已驗版本的純模型只在明確來源與資料契約內接管，不藉擴大名稱特例宣稱未來版本相容。未知遊戲版本或新模組規則先回原生，重新驗證後才擴充支援；不要求玩家更新本模組才能繼續使用原生計算。

黑箱學習的門檻、條件及跨重生紀錄只是可失效提示；觀察不足不得視為已證明規則。遊戲版本或模組規則改變時清除學習，重新觀測。正式路線優先減少重複工作、限制單幀工作量、保留原生試算與推薦品質核對。未知依賴的持久收益快取、少數採樣推斷整段線性，均不能保證品質，不直接啟用。

現有診斷probe不匯入產品、不於正常遊戲執行。第二建築介入擴充在執行前撤回，避免繼續將解鎖機制重建為產品規則引擎。

固定條件紀錄仍符合使用者要求：相同遊戲／模組規則下可重用已驗證門檻與先決關係，重生只重新判定實際天堂升級、永久欄位及當輪狀態。這不代表將內部規則重寫成真值；黑箱資料可作提示，特殊／隨機條件持續讀取實際結果，未知或失配回退原生。

## 推薦容差與批次黑箱候選

使用者接受數值誤差，只要實際推薦前三項的身分及順序一致。新的assessTopThree獨立於嚴格數值驗收；不自行以分數重排，也不以前三一致代替可負擔／購買安全檢查。所有候選仍須保護正式存檔、保存原始量測與未知規則回退。

早期scripts/perf隔離原型不重寫產量公式：bulk100先以原生CalculateGains取得終點，僅中間cps／raw用線性插值，價格與銀行等待維持逐筆原生路徑；tier ownership變動即原生重算，finally原生恢復基底。這保留原生終點小增量的浮點行為。起點必須有效；端點吻合不能證明任意內部條件、第三方hook或閉包沒有非線性／副作用。後續產品接入只開放可選實驗，不作嚴格模式的預設路徑。

端點近似已作可選實驗接入：每次更新輪替核對一棟建築，未核對或超過10秒者使用原生；失配立即停用，整輪重算並清除策略快取。它不是嚴格投影，也不是黑箱規則學習。兩次核對間仍可能推薦不同，因此預設關閉；不能以前三一次通過消除未知非線性風險。銀行門檻不加epsilon放寬。

稀疏採樣反例已固定於batch-candidate.test.mjs：原生收益僅第25步暫時增加100，第1／50／100步仍線性，現有fallbacks=0。此為拒絕把抽樣guard當未知規則保證的直接證據；全域排序oracle或明確支援邊界仍必要。

## 開發驗證分層與購買批次

日常先跑無UI單元測試，涵蓋公式、快取失效、銀行額、隱藏中間效果與10/100倍數目標。真遊戲整合保留Electron/DOM及相同模組；`dev.ps1 functional` 已提供隱藏視窗功能驗證，不以背景節流環境的幀率判效能。最終性能驗收仍使用可見副本、同快照、15秒暖機／60秒量測／各3輪。暫不抽離並維護另一份遊戲核心，避免與實際DOM/模組環境失真；正式效能採樣仍拒收hidden。

bulk10/100建築試算先補至下一倍數，後續步以整批探索。自動購買先原生沙盒預檢整批價格；開啟銀行時再檢查各步保留額，不足時不開始。預檢通過後一次原生buy(補齊數量)，不以逐件購買模擬批次。原生buy內的未知第三方副作用仍需實購觀察，不能宣稱預檢保證任意hook安全。可選近似僅支援bulk100且待補超過5單位，其餘維持原生；詳見README。

## 排除項目的納入建議

目前`isIgnored`排除toggle、vault及使用者關閉的Grandmapocalypse／Wizard tower；商店畫面另略過toggle與vault。既有設定已可納入後兩類；vault應尊重玩家選擇，不因推薦分數自行解除。

toggle會改變持續消耗、黃金餅乾出現或可逆狀態，單次CPS回本分數不足以表達。建議先提供獨立「策略提示、手動確認」，明列成本與條件；不直接加入自購。只有已證明是永久、無持續成本的一般升級，才走原生沙盒比較，再驗證前三、購買條件與副作用。新遊戲／模組升級不能只依名稱或pool自動列白名單。本輪為納入建議，未擴張自動購買範圍。
